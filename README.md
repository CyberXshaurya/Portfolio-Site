| Research result | Value |

The final system uses memory-safe sliding-window inference for high-resolution samples without boundary artefacts or out-of-memory failures.

```text
Portfolio-Site/
│
├── index.html
│
├── assets/
│   ├── content.js        # Portfolio data and editable content
```

The website deliberately separates **content**, **visual styling** and **interaction logic**, making future updates safer and faster.

## ☁️ Deploy on Render

### One-Click Blueprint Deployment

<p>
  <a href="https://render.com/deploy?repo=https://github.com/CyberXshaurya/Portfolio-Site">
    <img src="https://render.com/images/deploy-to-render-button.svg" alt="Deploy to Render">
  </a>
</p>

The repository contains a `render.yaml` file that configures the website as a static Render service.

### Manual Static-Site Deployment

1. Open the Render dashboard.
2. Select **New → Static Site**.
3. Connect `CyberXshaurya/Portfolio-Site`.
4. Use the following configuration:

```text
Branch: main
Root Directory: leave blank
Build Command: echo "Static portfolio ready"
Publish Directory: .
Environment Variables: none
```

5. Select the free option and deploy.

> This website does not require a Start Command because it is a static frontend rather than a continuously running backend service.

### Blueprint Error Fix

When Render displays:

```text
services[0].plan no such plan free for service type web
```

remove this line from `render.yaml`:

```yaml
plan: free
```

Static Render services do not require the `plan` field inside the Blueprint.

## ✍️ Update Portfolio Content

Most editable content is centralised inside:

```text
assets/content.js
```

Update the following sections:

| Section | Controls |
|---|---|
| `profile` | Headline, summary, contact and social links |
| `proofPoints` | Hero metrics |
| `projects` | Projects, descriptions, links and results |
| `capabilities` | Engineering strengths |
| `stack` | Technology groups |
| `timeline` | Education and leadership |
| `achievements` | Highlighted outcomes |

### Add a New Project

Copy an existing object from the `projects` array and update:

```javascript
{
  id: "unique-project-id",
  index: "07",
  title: "Project title",
  short: "One-line project summary",
  type: "AI Product",
  source: "GitHub",
  year: "2026",
  tags: ["Python", "FastAPI"],
  metrics: [],
  details: [],
  repo: "https://github.com/...",
  live: "https://..."
}
```

The interface generates the project card, filter entry and detail modal automatically.

### Update the Résumé

Replace:

```text
ShauryaCV.pdf
```

with the latest PDF while keeping the same filename. Every résumé link on the website will continue working automatically.

## 🔒 Privacy and Contact Behaviour

The contact form opens a pre-filled email draft using `mailto:`.

This approach means:

- No visitor message is stored
- No database is required
- No form API is required
- No server is required
- No secret key is exposed
- Deployment remains free

A hosted form service or custom backend can later be connected inside `initContactForm()` in `assets/app.js`.
